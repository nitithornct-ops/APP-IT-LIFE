# การลบผู้ใช้งานด้วยตนเอง

หน้า **จัดการผู้ใช้งาน**: ระงับบัญชีก่อน แล้วเลือก **ลบผู้ใช้งาน**
หน้าต่างจะแสดงจำนวนข้อมูลอ้างอิงและให้เลือก:

- **ลบบัญชีเข้าใช้งานและเก็บประวัติ**: ใช้ Supabase Auth soft deletion ซึ่งย้อนกลับไม่ได้ บัญชีเข้าสู่ระบบไม่ได้และหายจากรายชื่อจัดการผู้ใช้ แต่ชื่อและ profile ID รวมถึง Ticket, Task, ไฟล์แนบ และข้อมูลอ้างอิงยังอยู่
- **ลบถาวร**: ใช้ได้เฉพาะบัญชีที่ไม่มีข้อมูลอ้างอิงที่ขัดขวางการลบ

ทั้งสองแบบต้องกรอกเหตุผลอย่างน้อย 3 ตัวอักษรและยืนยันผลกระทบ ห้ามลบบัญชีตนเองหรือผู้ดูแลระบบสูงสุดคนสุดท้าย
บัญชีที่ลบแบบเก็บประวัติเปิดใช้งานใหม่ไม่ได้ ชื่อผู้ใช้และรหัสพนักงานเดิมยังถูกเก็บไว้สำหรับประวัติ

## การนำขึ้นระบบ

ใช้ migration `supabase/migrations/20261122210000_user_history_preserving_deletion.sql`
กับฐานข้อมูลเป้าหมาย **ก่อน** deploy API และหน้าเว็บใหม่ เพราะ API ใช้คอลัมน์ `profiles.account_deleted_at`
trigger บน `auth.users.deleted_at` จะบันทึกสถานะ profile ใน transaction เดียวกับ Auth soft deletion
ถ้า guard ปฏิเสธ การลบ Auth จะ rollback และไม่ซ่อนบัญชีออกจากรายชื่อ

ไม่มีการรัน migration หรือลบบัญชีจริงจากการทดสอบในเครื่อง การทดสอบฐานข้อมูลใช้ PGlite แยกจากข้อมูลจริง

อ้างอิง: https://supabase.com/docs/reference/javascript/auth-admin-deleteuser
