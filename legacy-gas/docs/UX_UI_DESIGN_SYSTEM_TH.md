# LIFE UX/UI Design System

คู่มือนี้เป็นมาตรฐานกลางสำหรับหน้าหลังบ้านทั้งหมด ได้แก่ Dashboard, Asset, Incident, Ticket, Risk, Audit, Vendor, Knowledge Base, Notification และหน้าจัดการอื่น ๆ

## 1. โครงสร้างหน้ามาตรฐาน

ลำดับจากบนลงล่าง:

1. Sidebar: เมนูแบ่งกลุ่มตามงานและสิทธิ์ผู้ใช้
2. Topbar: ปุ่มเมนู, ชื่อหน้าปัจจุบัน, ค้นหาด่วน, accessibility, notification และผู้ใช้
3. Breadcrumb: `ระบบจัดการ > กลุ่มงาน > หน้าปัจจุบัน`
4. Page header: ชื่อหน้า, คำอธิบายสั้น และปุ่มดำเนินการ
5. KPI cards: แสดงสถานะที่ต้องรับรู้ก่อนรายละเอียด
6. Filter / search toolbar
7. ตาราง, ฟอร์ม หรือเนื้อหาหลัก

ใช้ `pageHeader(title, subtitle, actionsHtml, icon)` สำหรับหัวหน้า และ `moduleDashboard(stats)` สำหรับ KPI เพื่อให้ทุกโมดูลมีโครงเดียวกัน

## 2. Typography

- ฟอนต์หลัก: Sarabun
- Body: 15.5 px, line-height 1.55
- Page title: 24 px / weight 800
- Section title: 16 px / weight 700
- Label: 13–14 px / weight 700
- Helper text: 12–13 px
- ระยะห่างหลักใช้ชุด 4, 8, 12, 16, 20, 24 และ 32 px
- หลีกเลี่ยงข้อความอธิบายยาวในตาราง ให้เปิดรายละเอียดใน modal แทน

## 3. ระบบสี

| บทบาท | สี | การใช้งาน |
|---|---|---|
| Primary | `#1D4ED8` | CTA หลัก, active navigation, focus |
| Primary dark | `#173A8A` | หัวข้อและข้อความเน้น |
| Surface | `#FFFFFF` | card, modal, form |
| Background | `#F1F5FB` | พื้นหลังระบบ |
| Text | `#1E293B` | ข้อความหลัก |
| Muted | `#64748B` | คำอธิบายและ metadata |
| Success | `#16A34A` | สำเร็จ, พร้อมใช้งาน |
| Warning | `#D97706` | ใกล้ครบกำหนด, ต้องตรวจสอบ |
| Error | `#DC2626` | ผิดพลาด, เกินกำหนด, destructive |

ใช้สีร่วมกับ icon หรือข้อความเสมอ ไม่ใช้สีเพียงอย่างเดียวเพื่อสื่อสถานะ ระบบรองรับ dark mode และ high contrast จาก topbar

## 4. ปุ่มและ CTA

- Primary: หนึ่งปุ่มหลักต่อกลุ่มงาน เช่น `เปิด Ticket`, `เพิ่มทรัพย์สิน`, `บันทึก`
- Secondary / outline: งานรอง เช่น วิเคราะห์, จัดการหมวดหมู่, พิมพ์
- Danger: ใช้เฉพาะงานลบ ปิด หรือยกเลิกที่มีผลกระทบ
- ปุ่มในตารางควรใช้ icon + tooltip; หากพื้นที่พอให้มี label สั้น
- ขนาดกดขั้นต่ำ 40 px และบนมือถือควรขยายเต็มพื้นที่เมื่อเป็น CTA สำคัญ
- งานลบต้องเรียก `showConfirm()` และใช้ soft delete เมื่อ workflow รองรับ

## 5. ตารางและการค้นหา

ตารางที่สร้างด้วย `dataTable()` มีมาตรฐานดังนี้:

- ค้นหาข้อความเดียวครอบคลุมทุกคอลัมน์
- กรองตาม field สำคัญ
- ล้างคำค้นหาและตัวกรองได้ในคลิกเดียว
- เลือกคอลัมน์ที่ต้องการเห็น
- เรียงข้อมูลจากหัวคอลัมน์
- ส่งออก CSV เฉพาะผลลัพธ์ที่กรองแล้ว
- แบ่งหน้า 10 / 25 / 50 รายการ
- บนมือถือแสดงหนึ่ง record ต่อหนึ่ง card พร้อมชื่อ field

คอลัมน์ลำดับสำคัญควรเป็น: รหัส/ชื่อ, สถานะ, ผู้รับผิดชอบ, กำหนดเวลา และ action หลีกเลี่ยงการแสดงเกิน 6–7 คอลัมน์เป็นค่าเริ่มต้น

## 6. ฟอร์ม

- เรียงข้อมูลจากจำเป็นไปหาเพิ่มเติม
- ช่องบังคับต้องมี `*` และตรวจสอบก่อนส่ง
- ฟอร์มสร้าง/แก้ไขขนาดกลางใช้ modal เพื่อไม่พาผู้ใช้ออกจากบริบท
- ฟอร์มยาวแบ่งเป็น section หรือ tab
- แสดง helper text เฉพาะข้อมูลที่ผู้ใช้มีโอกาสกรอกผิด
- หลัง submit ให้ปิดปุ่มชั่วคราวและแสดง `กำลังบันทึก...`
- ข้อผิดพลาดต้องชี้ช่องที่ผิดและเลื่อน focus ไปยังช่องแรก

## 7. Status badge และ feedback

- Success: เขียวอ่อน + ข้อความเข้ม
- Warning: เหลืองอ่อน + ข้อความน้ำตาลเข้ม
- Error: แดงอ่อน + ข้อความแดงเข้ม
- Info / Active: ฟ้าอ่อน + ข้อความน้ำเงินเข้ม
- Neutral / Closed: เทาอ่อน + ข้อความเทาเข้ม

Toast ใช้กับผลลัพธ์สั้น ๆ, alert ใช้กับข้อมูลที่ต้องอ่านก่อนทำงาน, modal ใช้กับการตัดสินใจหรือข้อมูลรายละเอียด

## 8. Responsive behavior

- Desktop มากกว่า 992 px: sidebar คงที่และย่อได้
- Tablet 768–992 px: sidebar เป็น overlay, action wrap ได้
- Mobile ต่ำกว่า 768 px: ตารางเป็น record cards, filter เต็มความกว้าง, modal footer ติดด้านล่าง
- Mobile ต่ำกว่า 576 px: ซ่อนชื่อหน้าซ้ำใน topbar และใช้ breadcrumb บอกบริบท
- Mobile ต่ำกว่า 420 px: KPI เรียงหนึ่งใบต่อแถว

## 9. UX flow ที่ต้องรักษา

- Loading ที่สั้นกว่า 180 ms ไม่แสดง overlay เพื่อลดการกะพริบ
- Loading หลายคำขอพร้อมกันต้องไม่ปิดก่อนทุกคำขอจบ
- Empty state ต้องบอกว่าข้อมูลว่างเพราะอะไรและเริ่มต้นอย่างไร
- Confirmation ต้องระบุผลของการกระทำและข้อความปุ่มให้ตรงกับงาน
- Notification ต้องพาผู้ใช้ไปยังโมดูลต้นทางได้
- Keyboard focus ต้องมองเห็นชัด และทุก icon button ต้องมี `aria-label`
- ค้นหาเมนูด้วย Ctrl/Cmd + K ได้จากทุกหน้า

## 10. Checklist ก่อนเพิ่มหน้าหรือโมดูลใหม่

- ใช้ `pageHeader()` และ `moduleDashboard()`
- มี primary CTA เพียงจุดเดียวในแต่ละกลุ่ม
- ใช้ `dataTable()` หากเป็นรายการที่ต้องค้นหา/กรอง
- มี empty, loading, success และ error state
- ทดสอบที่ความกว้าง 1440, 768 และ 390 px
- ทดสอบ keyboard focus, dark mode และ high contrast
- ไม่ใส่สี, spacing หรือ border radius เฉพาะหน้าโดยไม่มีเหตุผล
