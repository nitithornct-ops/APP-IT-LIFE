# ธรรมาภิบาลกฎหมายและการปฏิบัติตาม

เอกสารนี้ใช้สำหรับติดตั้งและใช้งานโมดูล **กฎหมายและการปฏิบัติตาม** ของ App_LIFE

> โมดูลช่วยจัดเก็บข้อเท็จจริง หลักฐาน ผลประเมิน และการติดตามงาน ไม่ใช่คำวินิจฉัยทางกฎหมาย  
> สถานะการใช้บังคับต้องได้รับการยืนยันจากฝ่ายกฎหมาย, DPO หรือหน่วยงานกำกับที่เกี่ยวข้อง

## 1. หลังอัปโหลดโค้ด

1. รัน `setupSystem()` จาก Apps Script Editor
2. ตรวจว่าระบบสร้าง/เพิ่มคอลัมน์ให้ Sheet ต่อไปนี้โดยไม่ลบข้อมูลเดิม
   - `LegalRegister`
   - `ComplianceObligations`
   - `ComplianceAssessments`
   - `CorrectiveActions`
   - `RegulatoryNotifications`
   - `Incidents` (คอลัมน์การประเมินหน้าที่แจ้งภายนอก)
3. Deploy เป็น Web App เวอร์ชันใหม่
4. เปิด Tester / QA และตรวจว่า Build ID เป็น `2026.07.09.1` และ Schema เป็น `6/6`

## 2. สิทธิ์

- `ITAdmin`, `DPO`: เพิ่ม/แก้ทะเบียนกฎหมาย ข้อกำหนด ผลประเมิน และ CAPA
- `Executive`, `Approver`: อ่านข้อมูล
- การประเมินและบันทึกการแจ้งหน่วยงานกำกับใน Incident ทำได้โดย `ITAdmin`, `DPO`
- ทุกการเปลี่ยนแปลงบันทึกใน `AuditTrail`

## 3. Workflow กฎหมายและข้อกำหนด

1. **ทะเบียนกฎหมาย** — ระบุฉบับ หน่วยงานเจ้าของกฎ URL ทางการ เจ้าของข้อกำหนด และสถานะการใช้บังคับ
2. **ข้อกำหนดและมาตรการ** — แตกกฎหมายเป็นหน้าที่ที่ตรวจสอบได้ พร้อมความถี่ หลักฐาน และโมดูลที่เกี่ยวข้อง
3. **ผลการประเมิน** — บันทึกผู้ประเมิน ผล มาตรการที่มี หลักฐาน ช่องว่าง และวันทบทวนถัดไป
4. **CAPA** — เปิดแผนแก้ไขสำหรับผล `ไม่สอดคล้อง` หรือ `สอดคล้องบางส่วน` และติดตามจนตรวจสอบประสิทธิผลแล้ว

สถานะ `ต้องยืนยัน` ใช้กับข้อที่ยังไม่ยืนยัน applicability เช่น สถานะ CII, การเข้าข่ายผู้ให้บริการตาม พ.ร.บ.คอมพิวเตอร์ หรือขอบเขตประกาศ คปภ. รายการดังกล่าวไม่ควรถูกนำไปกล่าวว่าองค์กรปฏิบัติตามแล้ว

## 4. Workflow Incident และการแจ้งภายนอก

1. ผู้ใช้แจ้ง Incident ตามปกติ
2. IT/DPO กด **ประเมินการแจ้งภายนอก**
3. ประเมินแยก 4 ปลายทาง
   - สำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคล
   - เจ้าของข้อมูลส่วนบุคคล
   - สกมช./ThaiCERT
   - หน่วยงานกำกับอื่น เช่น คปภ.
4. บันทึกเหตุผลและฐานกฎหมาย แม้ผลเป็น `ไม่ต้องแจ้ง`
5. กด **บันทึกการแจ้ง** เพื่อเก็บ deadline, วันแจ้งจริง, เลขรับเรื่อง, ผู้อนุมัติ และลิงก์หลักฐาน

การกด **บันทึกแจ้ง DPO** เป็นเพียงการรับทราบภายใน ไม่ถือว่าแจ้งหน่วยงานภายนอกแล้ว

## 5. กฎหมาย/กรอบตั้งต้น

`setupSystem()` จะ seed รายการต่อไปนี้แบบไม่สร้างซ้ำ

- พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562
- พ.ร.บ.การรักษาความมั่นคงปลอดภัยไซเบอร์ พ.ศ. 2562
- มาตรฐานการรักษาความมั่นคงปลอดภัยสำหรับเว็บไซต์ พ.ศ. 2568
- พ.ร.บ.คอมพิวเตอร์ และที่แก้ไขเพิ่มเติม
- พ.ร.บ.ธุรกรรมทางอิเล็กทรอนิกส์ และที่แก้ไขเพิ่มเติม
- หลักเกณฑ์ IT Risk ของ คปภ. สำหรับบริษัทประกันชีวิต (สถานะ `ต้องยืนยัน`)

## 6. การอ่านคะแนน

- Dashboard และ Evidence Center เดิมแสดง **สุขภาพมาตรการควบคุม** จากข้อมูลปฏิบัติการ
- หน้า **กฎหมายและการปฏิบัติตาม** แสดงผลจาก Assessment ที่มีผู้ประเมินและหลักฐาน
- ห้ามใช้สุขภาพมาตรการควบคุมเดิมเป็นคำรับรอง Legal Compliance

## 7. Test acceptance

1. ITAdmin เพิ่มกฎหมายและข้อกำหนดได้
2. DPO บันทึก Assessment ได้ และ AuditTrail มี `ASSESS_OBLIGATION`
3. ผลไม่สอดคล้องสามารถเปิด CAPA และติดตามสถานะได้
4. Executive เปิดอ่านได้แต่แก้ไขไม่ได้
5. Incident บันทึกการประเมินหน้าที่แจ้งภายนอกได้
6. หากเลือก `ไม่ต้องแจ้ง` แต่ไม่กรอกเหตุผล ระบบต้องปฏิเสธ
7. เมื่อบันทึก `แจ้งแล้ว` ต้องเห็นวันแจ้ง เลขรับเรื่อง และหลักฐานในแท็บการแจ้งหน่วยงานกำกับ
8. Evidence Center ใช้คำว่า “สุขภาพมาตรการควบคุม” และชี้ไปยังโมดูลกฎหมายสำหรับผล Legal Compliance
