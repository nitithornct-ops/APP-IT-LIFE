# 2. โครงสร้างฐานข้อมูล Google Sheets (Schema)

ใช้ Google Sheets **1 ไฟล์** — แยก **1 Sheet ต่อ 1 ทะเบียน/โมดูล** สร้างอัตโนมัติด้วยฟังก์ชัน `setupSystem()` ใน `Setup.gs` (อ้างอิงนิยามใน `Config.gs > DB_SCHEMA`)

source รุ่นปัจจุบันใช้ **Schema version 13**; การอัปเกรดเป็น v1.11 เพิ่มชีต/คอลัมน์ที่ขาดแบบ additive โดยไม่ลบ สลับ หรือเปลี่ยนชื่อคอลัมน์เดิม สถานะ Production migration ยังเป็น **Pending deployment**

**คอลัมน์มาตรฐาน** ที่ทุก Sheet (ยกเว้น `AuditTrail`, `NotificationLog`, `PolicyMapping`) มีท้ายตาราง:
`Timestamp` · `CreatedBy` · `LastUpdatedBy` · `LastUpdatedAt`

ประเภทข้อมูล: `Date` = วันที่, `Text` = ข้อความ, `Enum` = ค่าจากชุดที่กำหนด, `Email` = อีเมล

---

### 1) Users — ทะเบียนผู้ใช้งานและบทบาท
| คอลัมน์ | ประเภท | คำอธิบาย |
|---|---|---|
| UserID | Text | รหัสผู้ใช้ (USR-...) |
| EmployeeCode | Text | รหัสพนักงานสำหรับผูกกับ LINE Login (ต้องไม่ซ้ำ) |
| Username | Text | ชื่อเข้าสู่ระบบ ไม่ใช้อีเมล และห้ามซ้ำ |
| Email | Email | อีเมลสำหรับ MFA/การแจ้งเตือนและการอ้างอิงข้อมูล |
| FullName | Text | ชื่อ-สกุล |
| Department | Text | หน่วยงาน/ส่วนงาน |
| Role | Enum | User / Approver / ITAdmin / Executive / DPO |
| Supervisor | Email | อีเมลหัวหน้างาน (ใช้ route การอนุมัติ) |
| Status | Enum | Active / Inactive (Inactive = ระงับการเข้าใช้) |

### 1a) Employees — ทะเบียนพนักงาน

### 1a2) EmployeeAssignments — ทรัพย์สินและสิทธิ์ใช้งานรายพนักงาน

| IPHint | Text | (สงวน — Apps Script ไม่ให้ IP โดยตรง) |

- `FormSchemaJSON`, `ChecklistJSON` และ `WorkflowJSON` เป็น JSON ที่ Server ตรวจรูปแบบก่อนบันทึก; ทุกการแก้ Catalog เพิ่ม `Version`
- `WorkflowDefinitionID` อ้าง definition กลาง; `FulfillmentTarget` จำกัดที่ access/ticket/asset/change และ `TargetMappingJSON` เป็น snapshot mapping ที่ Server ตรวจ/allowlist
